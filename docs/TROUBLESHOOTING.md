# 故障排查（Troubleshooting）

本文按现象列出 Super Kanban 常见问题的排查步骤。安装、更新与版本验证的基础操作见 [INSTALL.md](INSTALL.md)。

## 更新后 UI 未变

**典型表现**：已经“更新”过插件，但页头「⋯」里仍有「设置」「在右侧栏打开」，或卡片没有状态点/优先级颜色/进度线——说明加载的仍是 0.3 的旧 bundle。

### 原因一：profile 依赖是旧范围，semver 不会跨 minor（最常见）

早期安装可能把依赖记成 `^0.3.0`。语义化版本中 `^0.3.0` 等价于 `>=0.3.0 <0.4.0`，**永远不会解析到 0.4.x**，所以无论怎么点更新/刷新，磁盘上仍是 0.3.x。

按 [INSTALL.md 2.3 节](INSTALL.md#23-命令行查看实际安装版本) 检查：

```bash
node -p "JSON.parse(require('fs').readFileSync(require('os').homedir() + '/.dsh/profiles/desktop/package.json', 'utf8')).dependencies['dsh-super-kanban']"
node -p "require(require('os').homedir() + '/.dsh/profiles/desktop/node_modules/dsh-super-kanban/package.json').version"
```

- 跨 minor 升级时，按 [安装指南第 3.2 节](INSTALL.md#32-推荐升级步骤所有安装方式通用) 卸载后安装目标精确版本。
- 如果依赖是 `link:/path/...`：这是源码安装，升级方式是更新该目录的代码（`git pull` / `git checkout v0.9.0` 固定到目标版本），刷新窗口即可；各安装方式的「安装特定版本」示例见 [INSTALL.md 第 1 节](INSTALL.md#1-安装四种方式)。

### 原因二：客户端 bundle 缓存 / 旧进程

1. 先按 `Cmd+R` 刷新窗口；
2. 无效则**完全退出 DSH**（不是只关窗口）再重新打开；
3. 再无效则确认没有同时打开多个 DSH 实例/窗口占用同一个 profile。

### 原因三：装到了别的 profile / 看错插件

DSH 桌面版使用 `desktop` profile；如果你在隔离 home（`DSH_HOME=/path/to/home`）里安装，桌面 App 看到的仍是原来的 profile。校验时请对**实际正在使用的 profile** 执行命令。

### 仍不生效

按 [INSTALL.md 第 3.5 节](INSTALL.md#35-更新后界面仍旧4-步快速排查) 走完整 4 步；再不行则卸载插件、重启 DSH、重新安装目标精确版本
（如 `dsh-super-kanban@0.9.0`；市场版本列表、npm 精确版本、Git tag 等写法见 [INSTALL.md 第 1 节](INSTALL.md#1-安装四种方式)），
并带上 [诊断信息](#如何收集诊断信息) 反馈。回滚步骤见 [INSTALL.md 第 4 节](INSTALL.md#4-回滚到旧版本)。

## 入口缺失

**表现**：插件已安装/启用，但左侧栏没有「任务看板」，会话头部也没有看板图标。

1. **刷新/重启**：`Cmd+R`；仍没有则完全退出 DSH 再打开。
2. **确认已启用**：DSH → 插件 → 已安装 → Super Kanban 状态为已启用（禁用状态不会注册入口）。
3. **确认入口偏好**：左侧栏打开全局看板。会话页头的形态选择器可切换三种入口，常驻悬浮入口单独在「设置 → 显示与入口」开启。若勾选了空闲时隐藏，摘要都为零时可以用形态选择器临时打开。
4. **确认插件加载成功**：插件页会显示加载失败原因（常见：DSH 版本不满足 `engines`、profile 清单错误、包文件不完整）。如显示不兼容，安装与当前 DSH 兼容的版本。
5. **确认 profile**：见上一节「原因三」。
6. **重装**：卸载 → 重启 DSH → 重新安装精确版本。
7. 仍没有：收集 [诊断信息](#如何收集诊断信息) 并反馈（插件加载错误全文最关键）。

## 看板空白或加载失败

**表现**：能看到看板框架但内容空白、一直骨架/加载、或出现「连接异常」横幅。

1. **刷新窗口**：`Cmd+R`；再看是否恢复。
2. **看控制台错误**：打开 DSH 开发者工具（如可用），查看 `/super-kanban/api/*` 请求状态与控制台异常。
   - 401/403 → 见 [API 返回 401/403](#api-返回-401403)；
   - 404 → profile 未加载插件或路由未注册，按「入口缺失」排查；
   - 500 → 看 host 日志与数据文件（见下）。
3. **数据文件损坏**：插件会把损坏的 `state.json` / `sessions-cache.json` 移到 `~/.dsh/storages/super-kanban/backups/` 并以空状态重建。若长时间空白，可先把 `~/.dsh/storages/super-kanban/` 备份后删除 `state.json`，重启让插件重新扫描生成。
4. **DSH 版本**：确认 DSH 版本在 [兼容范围](../README.md#兼容性) 内；大版本升级可能改变插件接口。
5. **多实例冲突**：关闭其他 DSH 窗口/实例后重试。

## API 返回 401/403

看板 API 只允许**当前 DSH 的 owner** 在同一会话/同源环境访问，这是有意的安全设计。

- **401**：没有有效登录态。请通过 DSH 窗口正常打开看板，不要用终端里的无 cookie 请求直接访问 `http://127.0.0.1:<port>/super-kanban/api/...`。
- **403**：登录态存在但不是 owner。常见于：
  - 用另一个浏览器标签/另一个 DSH 实例的地址访问当前实例的端口；
  - 远程访问（非本机回环地址）时权限不足；
  - 登录态过期后重新打开 DSH 窗口通常即可恢复。
- 排查时不要手动拼接 token；重新从 DSH 窗口进入看板最可靠。
- 如果你在开发环境调用 API，请使用该实例登录后的同源 cookie（见 [DEVELOPMENT.md](DEVELOPMENT.md)）。

## 扫描不跑、卡片不更新

1. **手动扫描**：点击页头的扫描按钮。运行中按钮显示 `N/M`，再次点击可取消。
2. **自动扫描开关**：设置齿轮 → 确认「自动扫描」开启，扫描间隔不要设得过长。
3. **活跃周期**：默认 30 天。更早且未更新的会话会跳过增量扫描。可以切换到「历史」查看旧任务，或在维护里手动扫描全部历史。
4. **工作区被排除**：设置 → 排除工作区，确认目标工作区没有被排除。
5. **会话是否变化**：增量扫描只分析**有变化**的会话（签名变化 / 用户消息增加 / 轮次结束），首次分析会研判一次，同一会话的两次 AI 研判至少间隔 180 秒。刚打开会话但未产生新消息时，卡片本来就不会变。
6. **AI 预算**：AI 超预算、达到每日上限或 10 分钟 AI 阶段墙钟时，会自动降级为规则引擎，扫描仍会更新卡片，只是研判颗粒度变粗；扫描结论会显示「剩余 N 个会话下次扫描继续」/「今日 AI 预算已用完（150/150）· 剩余 N 个会话明日继续」，不是丢数据。可在设置里切「自动 / 固定 N 次」、调高每日上限，或等下次扫描 / 次日继续。
7. **看扫描结果**：悬停扫描按钮或在「维护 → 扫描与存储」查看完整结论。失败后可点扫描按钮重试，持续失败时记录错误文本。
8. **没开 AI**：扫描按钮标题会变成「扫描（仅规则）」，扫描仍会更新卡片，只是全部由规则引擎研判。
9. **缓存问题**：删除 `~/.dsh/storages/super-kanban/sessions-cache.json`（先备份）后手动全量扫描，可强制重新解析全部会话。
10. **会话格式**：极端情况下会话日志损坏/格式升级会导致该会话被跳过（其余会话不受影响）；更新 DSH 与插件到兼容版本后重试。

## 项目或日程里找不到任务

1. 检查项目、时间范围、筛选条件和右侧看板的「当前会话」范围。从项目卡点「看板」「日程」或「时间线」会进入该项目范围。
2. 新绑定的工作区只影响之后的自动建卡。已有任务在「列表」选中后批量应用项目归属。
3. 日程显示未完成的任务。没有到期日的任务收在「未设到期日」里，打开卡片点「设置到期日」即可安排。
4. 旧卡可在「历史」或「全部时间」查找。时间线按事件日期过滤，任务仍在近期时也可能有历史记录。
5. 归档项目可在「项目 → 已归档项目」中查看和恢复。归档任务需打开筛选里的「含归档」。

## 快聊没有回答

1. 快聊上方显示看板的当前模型。点模型名称可切换。若跟随 DSH 默认，请在 DSH「设置 → 模型」确认已有可用的默认模型。
2. 连接中或回答中可以点「停止」。停止或失败会保留输入和部分回答，可编辑后重试。若提示上一次请求正在停止，等适配器完成清理后再试。
3. 追问使用同一模型最近的成功问答。换模型后从下一条重新记忆。「清空问答」可开始新话题；关闭快聊会清空弹窗记录。中英翻译只发送原文。

## AI 不生效或一直等待

AI 研判是**可选增强**；不生效时看板仍应使用规则引擎正常工作（卡片右上角标记为「规则」）。
从 v0.5 起，AI 请求不再由插件直连模型接口，而是经 **DSH 原生模型服务**（`ctx.llm`）发出；
模型目录、默认模型、第三方 provider 与凭证全部由 DSH 管理。

1. **AI 开关**：设置齿轮 → 确认「AI 联网研判」开启。关闭时扫描按钮会显示「扫描（仅规则）」。
2. **DSH 模型服务**：若扫描结论出现「当前 DSH 未提供 AI 模型服务，本次仅规则分析」，说明当前 DSH 版本/组合没有原生模型服务，升级 DSH 后可用；旧版本上 AI 会一直降级规则。
3. **模型解析**：看板默认**跟随 DSH 的默认模型**（在「DSH 设置 → 模型」里设置）；也可以在 **看板工具栏 → 选择模型** 中指定 provider/model。显式指定的提供方被删除/不可用时**不会自动换模型**，会规则降级并在扫描结论提示重新选择。
4. **凭证与登录**：凭证由 DSH 管理。未登录 / 未配置 API Key 时看板不会报错，只是规则降级；扫描结论会提示 `<provider> 没有可用模型（可能未配置 API Key 或未登录）`。请在「DSH 设置 → 模型」完成配置。
5. **模型目录**：打开「选择模型」看提示——「没有 provider」需要去 DSH 添加提供方；「有 provider 但 0 模型」多为凭证未配置；「已保存模型不在目录」时仍会先按原模型尝试，失败后规则降级，请重选或改为「跟随 DSH 默认」。
6. **预算**。设置显示「今日研判预算」、成功次数和 tokens。本地午夜重置，失败研判与润色也会消耗预算。扫描超时或达到上限后，规则引擎继续更新，待研判会话顺延。详见 [AI 预算与剩余会话](#ai-预算与剩余会话)。
7. **门控机制**：只有会话出现新变化（用户消息增加 / 轮次结束 / 首次 / 手动重新研判）才会调用模型；没有变化时不调用是正常的。
8. **网络/代理**：请求由 DSH 的模型适配器发出；网络受限、代理配置异常或第三方服务故障都会失败并自动降级。恢复后下一次扫描会重试。
9. **失败冷却**：单个会话研判失败后会冷却约 5 分钟再重试，避免每轮扫描反复烧预算；扫描结论会显示「N 个会话研判失败，5 分钟后重试」。
10. **手动重判**：打开任务抽屉 → 右上「⋯」→「重新研判」，只重判当前这张卡，不受全局扫描门控影响。扫描进行中会提示稍后再试；AI 不可用或超预算时会自动用规则引擎重判，并在 toast 中说明引擎与调用次数。
11. **看研判来源**。任务详情显示研判引擎、提供方、模型、时间和理由。来源会话出现晚于研判的新活动时，可从任务菜单重新研判。

## 接入第三方模型（或自定义模型 API）

看板**不在自己界面里**管理 API Key 或端点；第三方模型统一在 **DSH 设置 → 模型** 配置，看板只读取已配置的模型。

1. 打开 **DSH → 设置 → 模型**；
2. 添加模型提供方：
   - **第三方模型提供方**：从内置目录选择（OpenAI / Anthropic / OpenRouter 等）并填 API Key；
   - **自定义模型 API**：填写 Provider ID、端点、协议（OpenAI Chat Completions / OpenAI Responses / Anthropic Messages），用「获取可用模型」拉取模型列表并勾选，保存；
3. 回到看板 →「选择模型」→ 点「刷新模型目录」→ 选择刚配置的 provider/model（或保持「跟随 DSH 默认」）；
4. 点「应用模型」。快聊和后续扫描、重新研判、润色共用此选择。

注意：

- 凭证由 DSH 的 credentials 机制解析，看板不读取、不保存；看板也不会修改 DSH 的模型配置。
- 选择非 DeepSeek 官方/账号的第三方模型时，该提供方会收到功能所需的会话摘要、润色草稿或快聊文本。各用途发送的字段见 [隐私说明](../SECURITY.md)。
- 目录为空或加载失败：确认 DSH 设置里 provider 已保存且已填 Key，再回看板点「刷新模型目录」；目录读取失败后可继续使用已保存的模型。模型调用失败时，扫描会使用本地规则。

## AI 预算与剩余会话

- **预算模式**（设置 → AI 预算）：
  - **自动（推荐，默认）**：本次预算 = min(本轮待研判会话数, 每日剩余额度)；AI 阶段最多约 10 分钟，超出后剩余会话下次扫描继续。
  - **固定 N 次**（20 / 40 / 80 / 150）：单次扫描最多 N 次 AI 研判，超出后本次其余会话用规则卡，下次扫描继续研判。
- **每日上限**（默认 150，可选 10–500）是按**用户本地日历日**的预算单位上限（本地午夜重置），不是硬性成本上限：一次研判内部可能重试（单次最多 3 次请求），失败重试的请求/费用另计。
- **剩余会话**：扫描结论出现「剩余 N 个会话下次扫描继续」表示这些会话本轮只拿到规则卡（或尚未研判），**下次扫描会自动接着研判**；不会丢失，也不用手动重扫。达到每日上限时提示「今日 AI 预算已用完（150/150）· 剩余 N 个会话明日继续」。
- **想一次研判更多**：把单次上限切到「固定 150」，或把每日上限调高；大库首次全量可能跨多轮扫描完成。
- **失败会话**：研判失败的会话会冷却约 5 分钟再重试；扫描结论会给出失败数量。持续失败请见 [AI 不生效或一直等待](#ai-不生效或一直等待) 与 [接入第三方模型（或自定义模型 API）](#接入第三方模型或自定义模型-api)。

## 产物预览或终端不可用

**产物点不开**

1. 产物来自会话中的交付文件和写文件记录。历史卡片可能保留已移动或删除的文件路径。
2. 点击产物名后，DSH 会在产物来源会话的右侧栏打开预览，成功后关闭任务抽屉。
3. 文件名和已记录的路径可通过产物菜单复制。默认应用打开和文件管理器定位由 DSH 宿主的桌面环境处理，文件失效后仍可复制已记录的路径。
4. 若无法预览，检查来源会话与文件是否仍可访问。移动或重命名工作区也可能使旧路径失效。

**终端打不开**

终端入口依赖 DSH 右侧栏的终端能力；环境不支持时按钮会提示「当前环境不支持」。可改用 DSH 自带的终端入口。

## 右侧栏与全屏

- **打开右侧栏看板** · 在会话页头选择「右侧看板」，也可从右侧栏「+」工具列表打开「任务看板」。需要先打开一条会话。
- **宽度**：可拖动右侧栏左边缘。面板低于 620px 时显示单列与状态标签，较宽时显示四列。
- **全屏**：使用 DSH 右侧栏头部的全屏按钮；再次点击退出。全屏状态属于 DSH 布局，和插件数据无关。
- **希望页头图标默认打开右侧看板** · 在「设置 → 显示与入口」修改「会话页头默认打开」。

## 悬浮摘要找不到任务

1. 查看对应摘要是否已启用。默认开启「待验收」和「运行中」，可在「显示与入口」添加「待处理」。
2. 摘要只显示近期范围内未归档的任务。若任务正在运行或有会话请求，先打开对应会话。可验收的任务会显示「确认验收」。
3. 摘要若提示任务已更新，查看刷新后的证据再确认。「查看交付物」依赖 DSH 的文件预览，失败时可打开来源会话或任务详情。

## 卸载与数据保留

1. 插件页卸载 / `./uninstall.sh -y`；刷新窗口后入口消失。卸载脚本只移除本插件的依赖与 bundle 条目，
   **不会**整体覆盖 profile，不影响其他插件与配置。
2. **看板数据保留**在 `~/.dsh/storages/super-kanban/`，重新安装后会继续使用。
3. 想彻底清空：

   ```bash
   rm -rf ~/.dsh/storages/super-kanban
   ```

   删除前建议先备份或使用设置里的「导出 JSON」（文件名 `super-kanban-YYYY-MM-DD.json`）。

## 如何收集诊断信息

反馈问题前请准备（**不要包含 token、账号、真实会话原文**）：

1. **插件版本**：插件页显示版本 + [INSTALL.md 2.3 节](INSTALL.md#23-命令行查看实际安装版本) 的两条命令输出（实际版本、profile 依赖规格）。
2. **DSH 版本与操作系统**：DSH 关于页/安装包版本、macOS/Windows/Linux 版本。
3. **安装方式**：市场 / npm / Git / 本地目录 / `install.sh`。
4. **复现步骤**：从打开 DSH 到出现问题的操作顺序；是否在更新后出现。
5. **现象材料**：截图或录屏；DSH 开发者工具中 `/super-kanban/api/*` 的请求状态与报错文本；插件页的加载失败原因全文。
6. **数据状态**：`~/.dsh/storages/super-kanban/` 下的文件列表与大小（不需要内容）；`backups/` 是否有损坏备份文件。
7. **脱敏**：发送前删除 token、账号信息、真实路径与会话内容；安全问题请按 [SECURITY.md](../SECURITY.md) 私下报告，不要开公开 issue。

## DSH 升级后插件异常

插件依赖 DSH 的第三方插件接口，DSH 大版本升级可能改变接口或 `engines` 范围，表现为入口消失、加载失败或看板异常。

1. 安装与当前 DSH 兼容的插件版本（插件页会提示不兼容的 `engines` 范围）；
2. 完全退出 DSH 后重装插件；
3. 看板数据仍保留，升级/重装通常不会删除；
4. 若官方尚未适配，等待插件发布兼容版本即可；可用旧版 DSH 暂缓升级。
